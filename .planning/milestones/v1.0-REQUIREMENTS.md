# Requirements: Client Onboarding Agent

**Defined:** 2026-04-10
**Core Value:** Gather complete, actionable website requirements from non-technical clients through natural conversation

## v1 Requirements

### Agent Infrastructure

- [ ] **INFRA-01**: Dedicated openclaw agent `client-onboarding` with isolated workspace, agentDir, and sessions
- [ ] **INFRA-02**: Agent identity configured (name, emoji, theme via IDENTITY.md)
- [ ] **INFRA-03**: Auth profiles copied from main agent so API keys work
- [ ] **INFRA-04**: Web app sends `x-openclaw-agent-id: client-onboarding` header to route to correct agent
- [ ] **INFRA-05**: Gateway restart and connectivity verified via curl test

### Discovery Framework

- [ ] **DISC-01**: 5-phase progressive conversation flow (warm-up, business context, design direction, site structure, wrap-up)
- [ ] **DISC-02**: Tier 1 questions covered: business identity, target audience, website goals, pages/sitemap, design direction
- [ ] **DISC-03**: Tier 2 questions covered: CTAs, content readiness, competitor landscape, tone/personality
- [ ] **DISC-04**: Adaptive probing — agent asks follow-ups based on responses, not rigid script
- [ ] **DISC-05**: "I don't know" handling — offer examples, suggest industry defaults, mark as TBD rather than blocking

### Conversation UX

- [ ] **CONV-01**: Warm consultant personality — empathetic, approachable, uses plain language
- [ ] **CONV-02**: Warm acknowledgment of every answer before asking next question
- [ ] **CONV-03**: One question at a time (never multi-question dumps)
- [ ] **CONV-04**: Natural transitions between discovery phases with context bridges
- [ ] **CONV-05**: Progress indicators ("We're about halfway through" / "Just a few more questions")

### Output

- [ ] **OUT-01**: Markdown brief written to `briefs/YYYY-MM-DD-<company-slug>.md` in agent workspace
- [ ] **OUT-02**: Brief includes all Tier 1 + Tier 2 discovery categories with client's actual responses
- [ ] **OUT-03**: JSON block emitted in final assistant message matching `OnboardingWebsiteData` schema (businessName, industry, targetAudience, primaryGoals[], existingWebsite, brandingStatus, brandColors, competitorUrls[], desiredFeatures[], projectTimeline, budgetRange, additionalNotes)
- [ ] **OUT-04**: Null fields for unanswered questions (no guessing/hallucinating)
- [ ] **OUT-05**: `ONBOARDING_COMPLETE` sentinel included in wrap-up message for frontend detection

### Compatibility

- [ ] **COMPAT-01**: Works with existing SSE streaming response format (text/event-stream)
- [ ] **COMPAT-02**: Session continuity via `user: token` field in request body
- [ ] **COMPAT-03**: No changes to token generation, validation, or Firestore session lifecycle
- [ ] **COMPAT-04**: Brief output is a BONUS — web app extraction from JSON block is the primary data path

## v2 Requirements

### Multi-Agent Collaboration

- **COLLAB-01**: Onboarding agent can invoke Beacon (web-research) for competitor site analysis
- **COLLAB-02**: Post-onboarding handoff to a design agent for automatic mood board generation

### Enhanced Output

- **EOUT-01**: Structured JSON output suitable for Figma/mockup tool import
- **EOUT-02**: Branded PDF discovery brief with GannSystems logo
- **EOUT-03**: Auto-generated creative brief from discovery data

### Intelligence

- **INTEL-01**: Industry-specific question templates (e-commerce vs portfolio vs SaaS vs local service)
- **INTEL-02**: Mockup readiness scoring (completeness validation before handoff)
- **INTEL-03**: Smart follow-up scheduling when critical info is missing

## Out of Scope

| Feature                                         | Reason                                                        |
| ----------------------------------------------- | ------------------------------------------------------------- |
| Changes to gannsystems.pro-landing-page chat UI | Already works, only need one header addition                  |
| Per-client workspace isolation                  | Single agent with per-session context via token is sufficient |
| CRM/Notion/email integration                    | Markdown brief in workspace is sufficient for v1              |
| Multi-language support                          | English-only clients for now                                  |
| Voice/video intake                              | Text chat only, matching existing infrastructure              |
| Payment/contract generation                     | Separate workflow, not discovery                              |
